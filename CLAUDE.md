# Vantage — Frontend

Frontend for **Vantage**, a tour-booking platform and Kareem's first full-stack (MERN) project. Two goals: learn modern frontend deeply, and ship a portfolio piece impressive enough for LinkedIn, with storytelling, playful 3D, and easter eggs, without sacrificing accessibility or performance.

- **This repo** (`kareemayman/vantage-frontend`): the Next.js app, scaffolded with `create-next-app` (TypeScript, ESLint, Tailwind, `src/`, App Router, React Compiler, `@/*` alias).
- **API**: sibling folder `../backend` (GitHub: `kareemayman/vantage-backend`, renamed from `natours-backend`), Express 5 + Mongoose 9 on MongoDB Atlas. It is the source of truth for endpoints and data shapes: read the route and controller before integrating an endpoint, because the summary below can lag behind.
- **History**: Kareem hand-wrote the API (no AI) while following Jonas Schmedtmann's _Node.js, Express, MongoDB & More_ bootcamp ("Natours"), modernizing it along the way (Express 5 async errors, jose, Resend, Mongoose 9). The course's Pug SSR frontend was dropped on purpose; this repo replaces it with a summer/travel identity.

## Architecture

```
Browser ──▶ Next.js server on Vercel ──(server-to-server)──▶ Express API on Render ──▶ MongoDB Atlas
   └──────▶ Cloudinary CDN (images; the API stores Cloudinary public IDs)
```

- **The API owns business logic, validation, and data.** Next.js is the presentation layer plus a thin BFF (session cookie, data fetching, caching). Don't duplicate API rules in Next.js beyond client-side form validation.
- **Auth: BFF pattern (decided).** Signup, login, resetPassword, and updateMyPassword return a JWT in the JSON body. A Server Action (`src/lib/auth-actions.ts`) stores it in a first-party httpOnly cookie on the Next.js domain (`session`, set by `src/lib/session.ts`); server-only code forwards it as `Authorization: Bearer <token>` (the API's `protect` reads only that header). The token never reaches client JS, no CORS is needed, and the backend needs no auth changes.
  - Rejected: the API's own `jwt` cookie (third-party across `*.vercel.app` → `*.onrender.com`, blocked by Safari, invisible to the Next server, and `protect` never reads it); token in `localStorage` + Bearer from the browser (readable by any injected script, and the Next server can't see it, so no server-rendered logged-in UI).
  - JWTs live 2h (`JWT_EXPIRES_IN=2h`) with no refresh tokens: match the cookie's `maxAge`, and on a 401 clear the cookie and send the user to login.
  - `updateMyPassword` and `resetPassword` return a **new** token and invalidate the old one, so always replace the cookie.
  - Route protection: optimistic cookie check in `proxy.ts`, real check in the server data layer.
- All API calls live in `src/lib/api.ts`, which starts with `import "server-only"` (a build error if a Client Component imports it; Next 16 handles that import itself, so the `server-only` package isn't installed). `API_URL` is a server env var, never `NEXT_PUBLIC_`. Success is `res.ok`, never the body's `status`.
- **Caching**: public data (tours, reviews, stats) is cached on the Next side with `"use cache"` + `cacheTag`/`cacheLife`. Anything that reads cookies or user data is never cached across users.
- **Render's free tier sleeps after 15 min idle; the next request takes ~30–60 s.** Cached public pages must render without the API, live calls need a themed wait state (the plane loading screen), and a warm-up ping on first visit is worth considering.

## Backend API (summary)

Base path `/api/v1`. Local: `cd ../backend && npm run dev`. The port comes from `config.env` and is 3001 (moved off Next's 3000 in backend checklist item 0), so the local API is `http://localhost:3001/api/v1`. Protected routes need `Authorization: Bearer <jwt>`.

| Method | Path | Access | Success payload |
| --- | --- | --- | --- |
| GET | `/tours` | public | `results`, `data.docs: Tour[]` |
| GET | `/tours/:id` | public | `data.doc: Tour` (guides populated, **no reviews**) |
| POST/PATCH/DEL | `/tours`, `/tours/:id` | admin, lead-guide | bare `data: Tour`; 204 on delete |
| GET | `/tours/stats` | public | `data.stats: [{ toursCount, totalRatings, ratingsSum, avgRating, avgPrice, minPrice, maxPrice }]`: one group over every tour (`getTourStats`, backend item 4b). `avgRating` is the average of every review (each tour weighted by its `ratingsQuantity`), not rounded (4.608… with the seed data), so round it for display. `ratingsSum` is a helper the UI doesn't need and may go away |
| GET | `/tours/tours-within/:distance/center/:latlng/unit/:unit` | public | `results`, `data.tours` (`latlng` = `lat,lng`, `unit` = `mi` or `km`) |
| GET | `/tours/distances/:latlng/unit/:unit` | public | `data.distances: { name, distance }[]` |
| GET | `/tours/:tourId/reviews` | public (backend item 2) | `results`, `data.reviews` (user populated: name, photo) |
| POST | `/tours/:tourId/reviews` | role `user` only | `data.review`; body `{ review, rating }`; one review per user per tour |
| GET | `/reviews` | public (backend item 2) | `results`, `data.reviews` (tour populated) |
| GET | `/reviews/:id` | logged in | `data.doc` |
| PATCH/DEL | `/reviews/:id` | admin, user | bare `data: Review`; 204 on delete |
| POST | `/users/signup` | public | `token`, bare `data: User`; body `{ name, email, password, passwordConfirm }` |
| POST | `/users/login` | public | `token` only (status 201); body `{ email, password }` |
| POST | `/users/forgotPassword` | public | `message`; body `{ email }` |
| PATCH | `/users/resetPassword/:token` | public | `token`; body `{ password, passwordConfirm }` |
| GET | `/users/me` | logged in | `data.doc: User` |
| PATCH | `/users/updateMe` | logged in | `data.user`; only `name` and `email` are accepted |
| PATCH | `/users/updateMyPassword` | logged in | `token`; body `{ currentPassword, password, passwordConfirm }` |
| DELETE | `/users/deleteMe` | logged in | 204 (soft delete) |
| GET/PATCH/DEL | `/users`, `/users/:id` | admin | `data.docs`; `data.doc`; bare `data`; 204 (`POST /users` is a stub, use signup) |

- **Envelope**: `{ status, results?, token?, message?, data? }`, and the payload key varies by endpoint (see table). Branch on the HTTP status (`res.ok`), never the body's `status`, and keep doing so after backend item 16b fixes its spelling (`"Success"` from updateMe): `status` only repeats what the HTTP status says, and some responses have no JSON body to read (a 204, the rate limiter's plain-text "Too many requests", Render's error page while the API is down). Read the body for the data, and for `message` on errors.
- **Errors**: `{ status: "fail" | "error", message }`. In development the raw `error` and `stack` are added, and Mongoose validation, duplicate-key, and cast errors come back as **500** with raw messages; production maps them to 400 with clean messages.
- **Query features** (GET `/tours`, `/users`, `/reviews`): filter `?difficulty=easy&price[lt]=1000` (`gt|gte|lt|lte`); sort `?sort=price,-ratingsAverage` (default `-createdAt`); fields `?fields=name,price,slug`; paginate `?page=2&limit=9` (default limit 100, **no total count**). Look up a tour by slug with `?slug=the-sea-explorer` (returns an array; there's no dedicated endpoint until backend item 4c adds `GET /tours/slug/:slug`).
- GeoJSON coordinates are `[lng, lat]`, but the geo URLs take `lat,lng`.
- IDs: use `_id`. Tours and reviews also include a virtual `id`; users don't.

**Models** (fields the UI uses):

- **Tour**: `name` (10–40 chars, unique), `slug`, `duration` (days), `durationWeeks` (virtual), `maxGroupSize`, `difficulty` (`easy | medium | difficult`), `ratingsAverage` (defaults to 4.5 even with zero reviews, so show "New" when `ratingsQuantity === 0`), `ratingsQuantity`, `price`, `priceDiscount?`, `summary`, `description` (paragraphs split by `\n`), `imageCover`, `images[]`, `startDates[]`, `startLocation { coordinates, address, description }`, `locations[] { coordinates, description, day }`, `guides[]` (populated users).
- **User**: `name` (4–40), `email`, `role` (`user | guide | lead-guide | admin`), `photo?`. Passwords are at least 8 characters.
- **Review**: `review`, `rating` (1–5), `tour`, `user { name, photo }`. `createdAt` isn't returned. A populated `tour` or `user` can come back `null` until backend item 9b: deleting a tour leaves its reviews behind, and a deleted or deactivated user's reviews stay too. Skip reviews with no tour; decide how to show ones with no user when a page lists them.

## Design system

Theme: summer · travel · sky · beach · planes.

| Token | Hex | Role |
| --- | --- | --- |
| `navy` | `#1D5D9B` | primary: buttons, links, headings, dark sections |
| `sky` | `#75C2F6` | secondary: highlights, illustrations, sky gradients |
| `sun` | `#F4D160` | accent: CTAs, badges, highlights |
| `sand` | `#FBEEAC` | warm surfaces and backgrounds (sand-200; the page background is the lighter sand-50) |

Measured WCAG contrast: white on navy 6.8 ✓, navy on sand 5.8 ✓, navy on sun 4.6 ✓ (just passes AA), navy on sky 3.5 (large text only), white on sky 1.9 ✗, white on sun 1.5 ✗. **Text on sky or sun must be navy or darker, never white.**

**Tokens live in `src/app/globals.css`, and `/design` is the living style guide** (every token in light and dark; add each new component there).

- **Palette** (`@theme static`): 11-step scales (50–950) generated in OKLCH and contrast-checked, with Tailwind's default palette removed (`--color-*: initial`).
  - `navy`, `sky`, `sun`, `sand`; brand hexes at navy-600, sky-300, sun-300, and sand-200.
  - `neutral` (navy-tinted gray), `lagoon` (success green), `coral` (error red).
  - Raw colors are for illustrations, 3D, and art. **Components use semantic tokens.**
- **Semantic tokens** follow shadcn's naming, so shadcn components inherit them:
  - surfaces and text: `background/foreground`, `card`, `popover`, `muted`;
  - actions: `primary`, `secondary`, `cta` (the sun button), `destructive`;
  - `accent` (hover background for menu items);
  - status: `success/warning/info` each plus a `-soft` background, and `destructive-soft`;
  - lines and states: `border`, `input` (3:1 field borders), `ring` (focus), `disabled`, `overlay`;
  - each interactive color has `-foreground` and `-hover`, and primary also has `-active`.
- **Scene and cartoon-UI tokens** (from the handoff):
  - `outline` (bold cartoon borders), `tile`, `chip` / `chip-foreground` / `chip-warm`, `dash`, `night`, `crab`, `nav` / `nav-border`;
  - `scene-sky`, `scene-sky-2`, `scene-sea`, `scene-sand`, `scene-dune`, `scene-cloud`, `scene-cloud-shade`, `scene-ground-shadow`. The `scene-` prefix keeps them apart from palette classes like `bg-sky-50`;
  - `--wave-opacity` is a plain variable with no class.
  - **Tours page** (from `design/tours-handoff`): the plane window's `win-bezel`, `win-line` (navy-950 in both themes, unlike `outline`), `win-ring`, `win-ring-edge`, `win-empty`, and the shade's `shade`, `shade-ridge`, `shade-handle` (all classes, e.g. `bg-win-bezel`); `--shade-glow` is a plain variable (transparent by day, a sun glow at night). The sky is one token holding a whole gradient, `--sky-day` (`bg-(image:--sky-day)`): a day from morning through pink to the sunset by day, and from the night sky through plum to a dawn glow at night. Also `--sea-dusk` (the sea at the end of it), and `bg-card-lit`: `card` mixed with `--cloud-tint`, by as much as `--lit` says (0–100%), for clouds in later light. `sunset` (#f8a565, between coral-400 and sun-300) is a palette color, for the setting sun.
- **Shadows** are navy-tinted (`shadow-xs`…`shadow-xl`). `shadow-pop` is a hard cartoon "sticker" shadow (navy in light mode, sun in dark mode).
- **Radii and spacing:** Tailwind's defaults for now.
- **Buttons:** `ButtonLink` (`src/components/button.tsx`) for links that look like buttons. Variants: `cta` (the sun sticker, which presses down on click), `outline`, and `primary` (navy; everyday links like "View tour"). Sizes: `sm` (navbar) and `lg` (hero). The "go" arrow on links (`ArrowIcon`) and any other icon used in more than one place live in `src/components/icons.tsx`. There's no class-merging library, so `className` may only add layout (width, margins), never colors or sizes. The exception is a variant-prefixed override (e.g. `short:h-12`), because a variant class always wins over an unprefixed one. `Button` has the same looks as a real `<button>`, for actions that stay on the page ("Clear filters").
- **Logo:** the sunset on the sea (`<Logo>`, `src/components/logo.tsx`; Kareem's pick from five options, over a beach ball, the sun with a face, a plane on the sun and a plane window). It's in the navbar (26px, 20px on phones), the footer's wordmark (0.62em) and on the boarding pass (20px). Drawn for 20px and up. Raw palette colors; only the rim follows the theme (`stroke-outline`), or it would vanish on the dark navbar. Pointing at the footer's word makes the sun rise and set (`sunrise`, through `<Poke>`; this replaced the old dot's hop). `<Poke>` hides what's inside it from screen readers, so that link has `aria-label="Vantage"`.
  - **Browser icons** are Next's file conventions in `src/app/` (no config: Next writes the `<link>` tags). `icon.svg` is the source: the logo with a thicker rim and no small waves, for 16px; its rim lightens with `prefers-color-scheme: dark`. `favicon.ico` (16, 32 and 48px, daytime rim) is for browsers without SVG icons. `apple-icon.png` (180px) is the full logo on sky-100, because iOS fills see-through parts with black.
  - The last two are generated, so redraw them if the drawing changes: draw on a `<canvas>` in headless Chrome, read `toDataURL` through `--dump-dom`, and pack the .ico by hand (a 6-byte header, a 16-byte entry per picture, then the PNGs). Browsers hold on to old tab icons: close the tab and reopen it to see a change.
- **Dark mode:** light is the default for everyone, and dark is opt-in.
  - Dark values live under `[data-theme="dark"]`. Any element can carry `data-theme="dark"` or `"light"` to theme its subtree (themed sections).
  - `dark:` classes follow `data-theme` via `@custom-variant`, never the OS setting.
  - Prefer semantic tokens over `dark:` classes.
  - **How switching works:**
    - **Theme lives in the DOM, not React state:** `data-theme` on `<html>`.
    - Every switch calls `toggleTheme()` (`src/lib/theme.ts`). It saves to `localStorage` (`vantage-theme`) and runs the "sunset wipe": a View Transitions circle from the clicked button, or an instant swap with reduced motion or in browsers without support.
    - Triggers use `<ThemeToggle labelLight labelDark>` (`src/components/theme-toggle.tsx`), the only Client Component involved. It wraps any children: an icon, the hero sun, footer text.
    - Anything that differs per theme (icons, labels, copy) switches with `dark:` classes, never JavaScript, so server HTML is right for both themes.
    - The root layout runs `themeInitScript` as a plain inline `<head>` script (not `next/script`, which runs too late), so a saved dark theme never flashes light. `<html suppressHydrationWarning>` is required for this.
- **Base styles:** the page uses `background`/`foreground`, the default border color is `border`, every element gets a global `:focus-visible` ring, and text selection is sun-200.
- **Scrollbar** (`globals.css`, base styles): a sun sliding down the sky. The thumb is `cta` with a 2px `outline` border (`cta-hover` on hover and while dragging), and the track is `--sky-2`, so both themes come free. It's 15px wide, the same as Windows' default, so the layout doesn't move. It uses `::-webkit-scrollbar` (Chrome, Edge, Safari); Firefox gets flat colors from `scrollbar-color`. Phones keep their own thin bar. On a Mac it should replace the thin overlay bar with an always-visible one (not checked).
  - **Gotcha:** Chrome turns off every `::-webkit-scrollbar` rule on an element with `scrollbar-color` (measured: the outline goes and Windows' arrow comes back), and `scrollbar-color` inherits. So it's only set inside `@supports not selector(::-webkit-scrollbar)`. Don't set it anywhere else.
  - The rules are in `@layer base`, so a utility can still hide a bar (the Journey's swipe strip: `scrollbar-none`).
  - Dragging far off the bar and letting go snaps the page back to where the drag began. That's normal on Windows, and the browser's own bar does it too.
- **Gotcha:** Tailwind only generates classes it finds as complete strings in source files, so never build class names at runtime (`bg-${name}-500`). Use a full class name or an inline `var(--color-…)` style.
- **Fonts: Kareem chooses them.** Claude may recommend options when asked, but never picks one.
  - **Display (big titles): Oswald**, weights 200–700, as the free stand-in for Balboa, which Kareem wanted but which is paid (Adobe Fonts or a foundry license). Oswald was picked by rendering free candidates against real Balboa specimens. Use `letter-spacing: -0.02em` to `-0.025em` on headlines to match Balboa's tight spacing, except very large type (the hero's ~100–232px headline), which uses normal tracking to match the design.
    - Gotcha: an `em` letter-spacing is computed on the element that declares it, and children inherit the pixel value. Put `tracking-*` on the element that has the font size, not on a parent with a different size.
  - **Accent: Shadows Into Light** (handwritten, 400 only): postcard notes, doodled callouts, easter-egg labels, game scores. Not for body text, forms, buttons, or prices.
  - **Body: Figtree** (chosen over Nunito and DM Sans): paragraphs, forms, prices, buttons.
  - All three load through `next/font/google` in `src/app/layout.tsx` and map to Tailwind in `globals.css`. Use `font-sans` (Figtree, the default), `font-display` (Oswald; pair it with `tracking-tight`, which is -0.025em), and `font-hand` (Shadows Into Light).

## Conventions

- Server Components by default. Put `"use client"` on the smallest leaf that needs state, effects, or browser APIs.
- **Structure:** routes live in `src/app/`; shared components in `src/components/` (layout pieces in `src/components/layout/`), as named exports. Import with the `@/` alias.
- **Layout:**
  - The root layout renders `<SmoothScroll />` (draws nothing), the skip link, `<Navbar />`, the page's single `<main id="main">`, and `<Footer />`. Pages render `<section>`s and never their own `<main>`, and **every page renders `<PauseOffscreen />`** (see the loops note under Scene animation).
  - **Pages live in React's `<Activity>`** (a side effect of `cacheComponents`): Next keeps up to 3 visited pages alive, hidden with `display: none`, so the back button restores them instantly. Each folder level gets its own `<Activity>` (`/` has one inside `<main>`, `/tours` two), and React hydrates each one *after* the layout. So a layout effect must never touch the page's DOM: it runs before the page is hydrated, and any attribute it adds is a hydration error. When a page is hidden, its effects are cleaned up, and they run again when it's shown (not inside an R3F `<Canvas>`, see Conventions → 3D). Its state and refs stay.
  - `<html>` has no fixed height (no `h-full`): Lenis watches `<html>` grow to know how far the page scrolls. The body's `min-h-svh` keeps the footer at the bottom of short pages.
  - Page content is centered with `mx-auto max-w-6xl px-6`.
  - The navbar is `fixed` and floats over the page. Pages clear it with top padding (`pt-28 md:pt-36`); only the homepage hero sits under it on purpose. `scroll-pt-*` on `<html>` keeps anchor jumps and keyboard focus from landing under it.
  - Pages set `export const metadata = { title: "…" }`, and the root template turns it into "… | Vantage".
- **Mobile-first:** unprefixed classes apply at every size; `sm:`/`lg:` add from 640px/1024px. Check every page at 320px and 390px, and just under 1024px: a ~1025px browser window with a scrollbar lays out at ~1010px, so it gets the tablet (`md`) layout, not `lg`.
  - `short:` is a custom **height** breakpoint (`globals.css`): phone widths under 52rem (832px) tall, e.g. iPhone SE 375×667 or 360×780 Androids. The hero uses it to tighten up so the beach fits on the first screen. Check heroes at 375×667 too.
  - **Line breaks:** a title that could leave one word alone on its last line gets `text-balance` (CSS `text-wrap: balance`: lines of even length, never more lines; Where we go, the Journey), or a `<br />` where the exact break matters (the boarding pass and the Playground: "Your seat is / waiting"). Paragraphs and quotes get `text-pretty` (only fixes a lonely last word).
  - **Container queries** for a component that sits in spots of different widths (a card in a 1-, 2- or 3-column grid): `@container` on its wrapper, then `@sm:` etc. inside, which check the wrapper's width instead of the screen's. The luggage tag (`featured-tours.tsx`) switches to the design's roomy desktop sizes at `@sm:` (the tag is at least 384px wide).
- **Testing in the browser:** Kareem usually has `npm run dev` running on port 3000, and Next allows one dev server per project. Test against it instead of starting another, and never kill it.
  - **Kareem often runs the backend on 3001 too. Never stop a process on 3001 (or any port) without proof that Claude started it.** The backend's "Backend server is running on port 3001" line is not proof: Express 5 calls `app.listen`'s callback with the error when the port is taken, and `server.js` ignores it, so a second copy prints that line while Kareem's keeps the port. (This happened: Claude's copy failed silently and Claude stopped Kareem's, breaking his `/tours`.) Check the process tree instead: a Claude-started process descends from a `bash -c "source …/.claude/shell-snapshots/…"` shell, and its start time matches the tool call. To test with the API down, point one server at a dead port (`API_URL=http://localhost:3999/api/v1 npx next start -p 3100`; a shell variable beats `.env.local`) instead of stopping the real one.
  - **A fake API for down, slow and waking-up states** (used in 4e-1): a ~40-line `node:http` proxy on 3999 that forwards to the real API on 3001, logs every call, and switches modes with `GET /__mode?m=up|down|slow|slowdown&delay=40` (down: 503 at once; slow: the real answer after the delay; slowdown: a 503 after it). Build with it in `up` (the build needs the API), serve with `API_URL=http://localhost:3999/api/v1 node node_modules/next/dist/bin/next start -p 3100` (plain `node`, no `npx` wrapper, so stopping it leaves no child behind), then switch modes between clicks. It lived in a session scratchpad, so rewrite it when needed.
  - On this Windows machine, stopping a background task can leave its child processes running (a `next start` kept port 3100, a backend kept its database connections). Afterward, check the port and stop the leftover by PID after confirming its command line.
  - **The API allows 100 requests per hour per IP** (`express-rate-limit` in the backend's `app.js`), then answers 429, and Kareem's dev server shows a 500 for every page that needs the API until the hour is up (`Retry-After` in the 429's headers says how long). Dev mode asks the API again after every file save (the `"use cache"` copies are cleared), so dozens of scripted page loads while editing use it up: this happened in 5b step 2c. For many screenshots, test a production build on 3100: its pages are built ahead of time and never call the API (the build itself makes about 20 calls).
- **Screenshots:** headless Chrome's `--window-size` can't go narrower than ~500px and silently lies. For phone widths, use CDP `Emulation.setDeviceMetricsOverride` (verified: `innerWidth` reports 320) or a fixed-width `<iframe>` on a local host page. Screenshot `clip` coordinates are page coordinates, so add `scrollY` after scrolling.
  - **Comparing before and after pixel for pixel** (found in 5b step 2e): a script that scrolls fast leaves the entrances it passed paused halfway (`<PauseOffscreen>`), and while an animation is unfinished, Chrome draws everything after it on separate layers ("Overlap"). Text on such a layer is smoothed in gray instead of with colored subpixels, so whole sections "differ" for no real reason, and two runs of the same code can differ too. Compare in reduced motion, or with the other sections' animations switched off (injected `animation: none !important`). CDP's `LayerTree` domain (`compositingReasons`) shows which elements have their own layer and why.
  - The test browser keeps its profile between runs, so the footer's "Reduce motion" switch, saved in `localStorage`, carries over to the next run. A script that tests normal motion should clear `vantage-motion` first.
  - **Photos that never load in a screenshot** (found in 6a): with a reused profile (the script kills Chrome instead of closing it), lazy photos needing a size not downloaded before never started (`currentSrc` stayed empty), run after run, while cached sizes loaded. A fresh profile folder fixed it. Check the profile before suspecting the page.
- **Prefetching** (`partialPrefetching: true`, since Next 16.4): when a `<Link>` comes on screen, it downloads one shared "App Shell" per route, not one copy per link (production only: `next dev` doesn't prefetch). The shell can't hold anything that depends on the URL, so a page that reads `params` or `searchParams` (the tour page, the filters) must read them inside a `<Suspense>` boundary, or the dev overlay flags it ("URL data outside of Suspense"). That never blocks the build. `tours/page.tsx` is the example to copy. Measured on today's homepage: 10 prefetches with the option on or off, because `/tours/[slug]` doesn't exist yet; the saving should show up with step 5.
- **Next.js changes fast.** Before using a Next.js API, read the version-matched docs in `node_modules/next/dist/docs/`, because training data may be outdated (e.g. `middleware.ts` is now `proxy.ts`, `params`/`searchParams` are Promises, and caching is explicit via `"use cache"`).
- Zustand is for client UI/experience state only: menus, modals, the booking wizard, the wishlist (`persist`), the sound toggle, easter-egg progress and mini-game scores, and state shared between the R3F canvas and the DOM. Server data (tours, the current user) stays in Server Components. A store holding per-user data goes through a context provider, never a module-level singleton, because that would be shared across requests on the server.
- **Forms** (the login form is the example to copy: `src/components/auth/login-form.tsx` + `logIn` in `src/lib/auth-actions.ts`):
  - A Client Component form calls a Server Action through `useActionState` (`[state, formAction, pending]`). The action checks the fields with a Zod schema (`safeParse`, then `z.flattenError(...).fieldErrors`), calls the API through `api.ts`, and returns what the form shows; on success it `redirect()`s, outside any `try`.
  - `noValidate` on the form: every problem shows the same way, Zod's message under its field (`aria-invalid` + `aria-describedby`), with focus moved to the first field to fix. The API's own answer ("Invalid email or password") goes in a `role="alert"` box keyed by a try counter, so the same message is read out again.
  - React empties the form after every try: the action returns what was typed (never a password) and the field takes it back as `defaultValue`.
  - Field ids come from `useId()`: Next keeps visited pages in the document (`<Activity>`), so a plain `id="email"` could clash with another page's.
  - **Gotchas:** Zod 4's `z.email()` rejects spaces around the address (an `<input type="email">` trims them before sending). A form with a Server Action gets hidden `$ACTION_…` inputs from React, before the real fields, so test scripts must pick fields by `name`.
- **Popovers and menus** use the native `popover` attribute (`popoverTarget` on the button), so open/close, Esc, tap-outside, and the screen-reader "expanded" state come free.
  - Never put a display class (`flex`, `grid`, `block`) on the `[popover]` element itself: it overrides the browser's hidden-while-closed rule. Style an inner wrapper instead.
  - The layout (navbar) stays mounted across Next.js navigations, so a popover in it must close itself on link clicks (see `src/components/layout/menu-panel.tsx`).
- **Whole-card links:** a card that opens somewhere has one real link (e.g. "View tour", with the tour name added in `sr-only` text) plus `after:absolute after:inset-0`. Its invisible `::after` layer covers the card (which is `relative`), so a click anywhere hits the link and hovering anywhere lights it up. Don't wrap the whole card in `<a>`: screen readers would read every word as the link's name. The link itself must not get a `transform`, or the layer shrinks to the link's size.
- **Photos:** `next/image`'s `<Image>`, with a Cloudinary public ID as `src` (e.g. `tour.imageCover`); the global loader turns it into a Cloudinary link per width. With `fill`, the parent is `relative` with a size (e.g. `aspect-4/3`), and `sizes` must say how wide the photo shows at each breakpoint, in the layout's real numbers (e.g. `(min-width: 1280px) 352px, (min-width: 768px) calc(50vw - 36px), calc(100vw - 48px)`), or the browser assumes the full screen width and downloads too big a photo. Alt text from tour data. For an above-the-fold LCP photo, use `loading="eager"` or `fetchPriority="high"` (`priority` is deprecated in Next 16).
- **Tailwind reads every file in the project for class names**, except `.gitignore`d ones and `design/` (`@source not "../../design"` at the top of `globals.css`; the mockups' classes used to add rules like `.table` and `.filter`). **Gotcha:** once, after `next.config.ts` changed, the dev server kept serving CSS without a new class from an edited page (`aspect-4/3`) while a production build had it. Editing `globals.css` (or restarting the dev server) made it rebuild.
- **Spotting a class that doesn't exist:** `prettier-plugin-tailwindcss` sorts classes Tailwind doesn't know to the front. If `npm run format` moves a class to the start of the list, it does nothing. Found in 5b: v3's `shadow-inner` is gone in v4 (it's `inset-shadow-*` now).
- **Scene animation (CSS):** loops and entrances live in `globals.css` (section 5) as `--animate-*` theme variables.
  - Keyframes move the individual `translate`/`rotate`/`scale` properties, never `transform`, so a loop and a hover effect on different properties combine.
  - When two effects need the same property, nest elements: e.g. the wrapper takes the hover `scale` and the inner SVG takes the idle `translate`.
  - Always `motion-safe:animate-*`. SVG parts that spin or squash need `origin-center transform-fill`.
  - **Loops cost CPU for as long as they run.** `<PauseOffscreen>` (`src/components/pause-offscreen.tsx`) marks every page `<section>` and `<article>` and the footer `data-offscreen` while it's off screen, and one plain rule in `globals.css` (outside any `@layer`, so it beats the `animate-*` classes) pauses every animation inside. Paused animations carry on from where they stopped, so entrances scrolled past mid-play finish when you come back. Its observer is inset by 1px (`rootMargin: "-1px 0px"`), because a section that only touches the screen's edge counts as intersecting. Every page renders it (`src/app/page.tsx`, `tours/page.tsx`, `design/page.tsx`); a page without it leaves its loops and the footer's running. It used to sit in the layout, but once pages moved into `<Activity>` (phase 2 step 3) its effect ran before the page hydrated and marked sections early: React's "attributes of the server rendered HTML didn't match" error, on every load. A page that streams sections in behind a `<Suspense>` renders `<PauseOffscreen />` inside that boundary, after them, and gives it a `key` that changes when the sections do, because it only looks for them once (see `tours/page.tsx`).
  - **Gotcha:** a loop that moves a group *inside* an SVG drawing (`<g>`, `<path>`: the sun's rays, the ball's `rock`, the palm's fronds) makes the browser redo the page layout every frame. A loop on a whole `<svg>` or an HTML element only restyles it. `contain: layout paint` didn't help (measured). For new art, put a moving part in its own `<svg>` or HTML wrapper when you can.
  - **3D turns** (the flip-board tiles in `by-the-numbers.tsx`): `perspective-*` on the parent, and turn with `rotate-[x_90deg]`, which sets the `rotate` property like our keyframes. Tailwind's own `rotate-x-*` sets `transform` instead, so the two would stack. The browser draws anything turned in 3D on its own layer, where text can land a pixel off from its neighbors: once a piece has done its turn, hide it (`invisible`) instead of leaving it turned.
    - **A 3D entrance that ends flat** (the sticky notes' `stick-on`) puts the perspective inside its keyframes, `transform: perspective(…) rotateX(…)`, not as a `perspective-*` class on the parent: with the class, Chrome kept each note on its own layer after the entrance had finished (reason "PerspectiveWith3DDescendants", measured), so its text was drawn softer for good. This is the one place keyframes move `transform`: the perspective must apply after the turn, and only `transform` puts them in order. Size the perspective in `cqw` (a container on the wrapper), so a wide element doesn't swell past the page's edge as it turns.
  - An SVG drawing whose trick moves parts outside its box gets `overflow="visible"`. **Gotcha:** inside a grid or flex box, that stops it from shrinking below its natural size (it renders far too big), so the container gives it `min-h-0` (the Journey's picture panels use `*:min-h-0`).
  - **One-shot toy animations** (on click, tap, or hover) use `<Poke animation playOnHover?>` (`src/components/scene/poke.tsx`). It sets `data-playing` until the named keyframes end, and the CSS decides what plays (`data-playing:animate-hop` on the toy, or `group-data-playing:animate-bounce-once` on a child). The toy's markup stays in Server Components.
    - Don't use `hover:`/`active:` for one-shots. `:active` lasts only while the button is held, and setting the same animation again never restarts it.
    - With a `label`, the toy is a real `<button>` (the beach ball). Without one, it's decoration (the palm, suitcases): `aria-hidden`, mouse and touch only, not a Tab stop.
  - **Entrances that play once, on scroll into view:** wrap the thing in `<Reveal>` (`src/components/reveal.tsx`). It marks its box `data-reveal="waiting"`, then `"seen"` once the box's top is 25% up the screen, and the CSS decides the rest with the `waiting:` and `seen:` variants, e.g. `waiting:opacity-0 motion-safe:seen:animate-swing-in motion-reduce:seen:animate-fade-in`. Without JavaScript nothing gets marked, so nothing stays hidden.
    - Give each item its own `<Reveal>` when items should wait for themselves (stacked phone cards would otherwise play off-screen). Stagger with an inline `style={{ animationDelay }}`. **Gotcha:** not with a `[animation-delay:…]` class: `motion-safe:animate-*` sets the `animation` shorthand, which resets the delay to 0, and the variant's rule wins (measured on `Snooze`, fixed in 4e-2).
    - When an entrance moves its element far (the boarding pass slides in from a whole pass-height away), animate a child and keep the `<Reveal>` box itself still: the observer measures the box where it is, transforms included.
    - **An entrance whose last frame is the element's normal look uses `backwards`, not `both`.** `backwards` shows the first frame during the delay, which is what hides it until its turn. `both` also holds the finished animation forever, which keeps the element on its own layer, and its text turns lighter and softer (the luggage tags had this until 10b). Keep `forwards`/`both` only when the end must differ from the element's normal style.
    - Something that swings or slides near the screen's edge can make the page scroll sideways mid-animation: its section gets `overflow-x-clip` (it hides only the sideways overflow, so things that stick out above, like the tags' strings, still show).
  - **Entrances on the first screen** (the journal's cover) play on load: plain `motion-safe:animate-*` with `backwards` and an inline delay, no `<Reveal>`. `<Reveal>` only starts once the page's script runs, so a visitor would see the finished thing, then see it vanish and play. Don't keep the page's biggest element hidden behind a delay: it's what the loading score (LCP) waits for.
  - **Filling wrapped lines one after another** (the cover's highlighter and handwriting): a background or a mask on an inline `<span>` runs from the end of one line to the start of the next (the default `box-decoration-break: slice`), so growing its size from 0 to 100% fills line 1, then line 2, wherever the lines break. `box-decoration-clone` gives each line its own copy, and they all fill at once. Side padding on such a span only pads the first line's start and the last line's end. **Gotcha:** Chrome skips a zero-width mask on a span that wraps and shows the whole text, so `write` starts at 1px.
  - **A pen line drawing itself, in CSS** (the plan's ticks and circle): `pathLength={1}` on the `<path>` (its length counts as 1), and the `draw` keyframes (`animate-tick`, `animate-circle`) slide a dash as long as the line onto it, offset 1 → 0. The dashes only exist while it plays. The gap is twice the dash (`stroke-dasharray: 1 2`): with a plain `1`, a zero-length dash can land on the line's end, and a round cap draws it as a dot. A line that's already dashed can't do this (its dashes are taken): see the globe's stencil under Scroll animation.
  - **Effects that follow the mouse:** the script only writes a CSS variable, and a `motion-safe:` class turns it into motion, so reduced motion switches it off like everything else. E.g. `<TagHover>` (`src/components/home/tag-hover.tsx`) sets `--lean` from -1 to 1 on `pointermove` and the class is `motion-safe:rotate-[calc(var(--lean,0)*-2deg)]` with a short transition. Mouse only (`event.pointerType === "mouse"`): touch screens have no hover. Measure a box that doesn't move with the effect, or the numbers wobble.
  - **Easing a CSS variable** (the sticky notes' peel, `--peel`): a plain CSS variable can't be transitioned, it jumps. Registered with `@property` (a type, e.g. `syntax: "<length>"`, and an `initial-value`), it eases like a size or a color, and everything that uses it follows it every frame, so two parts drawn from one variable (the cut and the flap) can never drift apart. `transition-[--peel]` on the element, the new value on `hover:`.
  - **A `clip-path` that does nothing at rest still changes the edges** if its lines lie exactly on them: the edge pixels get smoothed twice and turn lighter (measured on the notes). Put the rest shape 1px outside the element (`peel-cut` in `globals.css`). A `clip-path` also cuts off the element's own shadow, so the shadow goes on a wrapper.
  - **Reacting to a hover somewhere else:** `group-hover:` only works inside the hovered element, and `peer-hover:` only on its later siblings. When a part must react to an element that's neither (the boarding pass's stub tears while "Explore tours" is hovered), a custom variant asks their shared box with `:has()`: `tearing:` in `globals.css` is `[data-pass]:has([data-tear]:hover) *`, wrapped in `@media (hover: hover)` like Tailwind's own `hover:`. No JavaScript.
- **Hero composition:** props near the headline sit inside the title "stage", whose font size is the headline size, and are positioned in `em` (`left-1/2 ml-[0.82em] top-[-1.69em]`). They scale and move with the headline at every width.
  - The hero's content layer is `pointer-events-none` so empty sky passes the pointer to the stars behind it; interactive children opt back in with `pointer-events-auto`.
  - **Gotcha:** the headline's tight `leading-[0.84]` makes its text catch clicks about 0.3em above its own box, because Chrome hit-tests by the font's full height. Toys that sit just above the headline need a layer above it (the plane layer is `z-20` and `pointer-events-none`).
- **Reduced motion has two sources:** the device setting, and the site's "Reduce motion" switch (footer), which puts `data-motion="reduce"` on `<html>`. It works like the theme: saved to `localStorage` (`vantage-motion`) and restored by the `<head>` script before the first paint.
  - `globals.css` redefines Tailwind's `motion-safe:` and `motion-reduce:` variants to check both, so always use those variants and every animation obeys automatically.
  - In JavaScript, use `prefersReducedMotion()` from `src/lib/motion.ts`, never `matchMedia` alone. A component that must react when either source flips (e.g. turning Lenis off) uses `useReducedMotion()` (`src/lib/use-reduced-motion.ts`).
  - Plain-CSS animations need `:root:not([data-motion="reduce"])` (see the navbar shrink).
  - If the device already asks for reduced motion, the switch hides (`[@media(prefers-reduced-motion:reduce)]:hidden`), since there's nothing to switch.
- **Smooth scroll (Lenis):** `<SmoothScroll />` smooths the mouse wheel site-wide; touch, keyboard and scrollbar stay native. It switches itself off with reduced motion. GSAP's ticker drives it, so scrolling and GSAP animations share one frame loop.
  - A box that scrolls on its own with the wheel (an overflowing panel or list) needs `data-lenis-prevent`, or Lenis scrolls the page instead. Touch-only scrollers (the phone swipe track) are fine.
  - **The loop sleeps when nothing glides.** Lenis's step on GSAP's ticker is removed after 30 frames without a smooth scroll (`lenis.isScrolling !== "smooth"`), and a `wheel` listener puts it back. Waking resets `lenis.time` to 0, because Lenis times each step from the frame before and a huge gap after a nap would make the glide jump straight to its end. With no listener and nothing animating, GSAP's ticker naps too (its `autoSleep`). ScrollTrigger keeps its own empty `requestAnimationFrame` loop (`_rafBugFix`, on purpose, for steady repaints) and a 250ms sync timer; both are cheap. If code ever calls `lenis.scrollTo()`, it must wake the loop first.
- **Scroll animation (GSAP):** import `gsap`, `ScrollTrigger` and `useGSAP` from `src/lib/gsap.ts`, which registers the plugins once.
  - Set up in `useGSAP` (it undoes every tween and pin on unmount, before React removes the DOM, which pins need). Use `gsap.matchMedia()` for per-breakpoint setups. Pass `useReducedMotion()` in `dependencies` with `revertOnUpdate: true`, and skip the motion setup when it's true. See `journey-track.tsx`.
  - **The no-JS layout is the default.** JavaScript switches into the animated layout by marking the section (`data-pinned`), and CSS restyles it with the `pinned:` variant (`globals.css`). While "riding" (phones swiping, or the pinned ride; the `riding` state in `journey-track.tsx`), React labels each card `data-stop="passed" | "here" | "ahead"`, and only then shows the progress bar. The calm grid gets no labels, so it looks finished. CSS reads the labels with one-line variants that use the same words: `here:` (the card the plane is at), `ahead:` (not reached yet), and `reached:` (here or passed). Kareem asked for this one vocabulary after an earlier version used different words in React and CSS. One-shot animations that react to the ride use `reached:`, not `here:`: when a card goes from here to passed, the animation stays attached and finishes instead of being cut off.
  - A pinned section must fit the screen: it's `min-h-svh`, and its big parts shrink with height via `min(<design size>, <a>svh - <b>)`, which keeps the design's size at 900px tall and still fits 657px (1366×768 laptops). The pin starts at `"bottom bottom"`, so if it ever overflows, the top is what's cut.
  - Pinning needs no `transform` (or `filter`) on the pinned element's ancestors, since `position: fixed` breaks under one. Use `scrub: true`, not a number: Lenis already smooths the scroll.
  - **Drawing a line in** (the globe's dashed flights, `globe.tsx` + `globe-flights.tsx`): a dashed line can't draw itself in (its dash settings are busy making the dashes), so it's seen through a stencil, an SVG `<mask>` holding a solid copy of the line with `pathLength={1}`. Animate the stencil's `strokeDashoffset` from 1 to 0 (with `strokeDasharray: 1`). **Gotcha:** GSAP rounds pixel values to whole numbers while animating, so a 1 → 0 tween needs `autoRound: false`, or it jumps halfway instead of drawing.
- **Animation that follows the scroll with no JavaScript** (the navbar's shrink, the tours page's setting sun): `animation-timeline`. The browser runs it in step with the scroll, even native touch scrolling, where a script is always a frame behind, and there's nothing to set up or clean up. GSAP is still the choice for a timeline that coordinates several things, or when a script needs to know the progress. The sun's version (end of `globals.css`):
  - `view-timeline-name: --sky` on the section makes its scroll position a timeline, and `animation-timeline: --sky` on anything inside it follows that instead of the clock. `animation-range: contain` runs from the section's top at the top of the screen to its bottom at the bottom of the screen.
  - It's plain CSS, not Tailwind classes: `animation-timeline` must come after the `animation` shorthand, which resets it, and class order isn't ours to choose.
  - **Gotcha:** the timeline respects `scroll-pt` on `<html>`, so it started 112px early and the animation was already 3% in on load. `view-timeline-inset: 0` on the section fixes that.
  - Guard it with `@supports (animation-timeline: view())` and the reduced-motion check, and decide what the page looks like without it.
  - `overflow-clip` on an ancestor doesn't stop `position: sticky`; `overflow-hidden` does. A `fixed` child isn't clipped by it either.
- **Moving something big every frame** (the cards in the wind, `wind.ts`): write `translate`, `rotate` and `scale` on one wrapper, with `will-change` while it moves, and clear them all at rest. Then the browser only slides a finished picture around. Nothing inside it may change: swelling each puff inside a card's `filter` repainted the card every frame (3.7 fps instead of ~20 in software rendering), while the sway alone costs nothing measurable.
- Motion and 3D: honor reduced motion (no Lenis smoothing or scroll-scrubbed motion; simple fades are fine). Load 3D client-only and lazily, pause it offscreen, and give low-power and mobile devices a static fallback. Animation must never block content or hurt LCP/INP.
- **3D (three.js + React Three Fiber):** 3D code lives in `src/components/three/`. R3F turns JSX into three.js objects (`<mesh>` is `new THREE.Mesh()`, `args` are the constructor's arguments), `<Canvas>` sets up the renderer, scene, camera and frame loop, and `useFrame` runs before every frame.
  - **Loading:** three.js only runs in the browser and is big (the 3D chunk is ~237 KB gzipped). A small Client Component loads each scene with `next/dynamic(…, { ssr: false })` (only allowed in Client Components), so the server never runs it and pages without 3D never download it. Example: `plane-preview.tsx` → `plane-preview-scene.tsx`. When a scene must wait for something, or a failed download needs a fallback, use a plain `import()` in an effect instead (`tour-route.tsx`).
  - **Pausing:** a scene draws 60 times a second unless told otherwise. `frameloop="demand"` (draw only when something changes) while it's off screen (an IntersectionObserver) or motion is reduced.
  - **The look** (the handoff's 3D style): `meshToonMaterial` with a 3-step `gradientMap` (`STEPS` in `plane-model.tsx`), `<Canvas flat>` (no tone mapping, so palette colors stay exact), and lights that add up to about π (a hemisphere light at 0.95 plus a directional sun at 2.2): that's what shows a fully lit spot in its exact color. More looks washed out.
  - **Outlines:** our own inverted hull (`outline()` in `plane-model.tsx`): a copy of each part pushed out along its normals, painted navy on its inside only. Not drei's `<Outlines>`: in drei 10.7.9 its `screenspace` flag is swapped (false measures in pixels, true in model units). Squash a shape in its geometry (`.scale()`), not with the mesh's `scale`, or the outline stretches unevenly.
  - **three.js is pinned to 0.182** (`^0.182.0` only allows 0.182.x): R3F 9.8.2, the latest, still creates a `THREE.Clock`, which three.js deprecated in r183, so newer versions print a console warning on every page with 3D. Move up once R3F switches to `THREE.Timer`.
  - **One object flying over a page:** a small `fixed` canvas that moves with it (CSS transform, to whole device pixels), not a full-screen one. It can afford to draw at 2× at least, and shrinking that is what smooths toon steps, which antialiasing can't reach, because it only smooths the edges of shapes. A `shadowMaterial` sheet should be small and follow the shadow.
  - **Don't copy the scroll into something that rotates:** the end of Lenis's glide is whole-pixel steps with growing gaps. Chase it instead (close part of the gap each frame, `1 - Math.exp(-rate * seconds)`, and `invalidate()` until it arrives).
  - **Pages hidden by `<Activity>`:** R3F keeps a scene alive while its page is hidden (its source: "Only final removal releases the root"). Effects inside the `<Canvas>` aren't cleaned up, so their listeners stay on, and refs keep their values. Next hides visited pages instead of removing them, so a scene that should start over on each visit has to be removed from outside the canvas: `setScene(null)` in the cleanup of the effect that loads it (`tour-route.tsx`). Coming back runs that effect again and makes a new scene. Kareem caught it: coming back to `/tours`, the plane was already on the cloud, because the same plane remembered it had flown in.
  - **Stopping a demand-drawn scene:** a smoothed number or a spring only ever shrinks toward 0, so a check for exactly 0 never comes true and the scene draws forever. Snap to rest below a small threshold (`STILL` and `settled` in `wind.ts`).
  - **Screenshots and timing:** headless Chrome has no GPU; launch it with `--use-angle=swiftshader --enable-unsafe-swiftshader` for WebGL. The "GPU stall due to ReadPixels" warnings come from capturing, not from the page. `Performance.getMetrics` only counts the main thread, not WebGL's drawing, which runs in another process: to compare two versions, measure frames per second during a scripted scroll. To see a fast CSS animation at an exact moment (screenshots take too long to catch it live): `document.getAnimations()`, `.pause()` each one, set its `.currentTime`, then shoot.
- Accessibility: semantic HTML first; everything keyboard-reachable with visible focus; alt text from tour data.
- Env: server-only `API_URL`. Use `NEXT_PUBLIC_` only for values that are safe to expose (e.g. the Cloudinary cloud name). Never commit `.env*` (`.gitignore` has `.env*`). `.env.local` holds `API_URL=http://localhost:3001/api/v1`; on Vercel, set the variables in the dashboard.
- Code style matches the backend and is enforced by Prettier (`.prettierrc`): no semicolons, double quotes, trailing commas, 100-column lines. Run `npm run format` after writing code. `endOfLine` is `"auto"` because git's `core.autocrlf=true` on this Windows machine checks files out with CRLF.
